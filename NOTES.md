# CCC | CoolColorCursor — как всё устроено

Заметки для того, кто продолжит проект (человек или ИИ). Дополняется по ходу работы. Последнее обновление: 2026-10-25.

## Что это
Утилита для Windows (Python 3 + PyQt5) для Dota 2: шлейф курсора, таймеры по данным GSI, сборки героев (Stratz), свой маркер клика внутри игры, сборки внутри магазина Dota. Запуск: `pythonw.exe main.py` (без консоли). Токен Stratz лежит в `api.txt` (в git не класть, в логи и чат не выводить).

## Правила проекта
- Всё «наше» (шлейф, таймеры, иконка, сборки) показывается только пока активна Dota 2.
- Файлы самой игры (`dota\pak01…`) не трогаем. Все наши моды лежат только в `game\dota_russian` (нужен параметр запуска Steam `-language russian`).
- Подмена файлов Dota — только с плашкой «на свой страх и риск, мы не несём ответственности за ваш аккаунт».
- Не делаем: подмену платных скинов, внедрение кода в процесс игры, дальнюю камеру (даёт преимущество в матче, риск бана).
- Паки читаются игрой только при запуске: при открытой Dota файл занят (`PermissionError`), нужно закрыть игру.

| `app/ingame_marker.py`, `app/marker_window.py` | маркер клика внутри Dota (пак с номером от 68) и его окно настроек |

| `app/rank_mod.py`, `app/rank_window.py` | свой вид ранга (свой пак): под именами настоящей медали/звёзд кладутся родные иконки выбранных (`panorama/images/rank_tier_icons/`, BGRA8888); «без звёзд» — прозрачная текстура; сторонние паки с иконками рангов из `dota_russian` убираются в `backup/ranks/` папки данных и возвращается кнопкой «Вернуть как было». Свои наборы иконок — `rank_sets/<имя>/` в папке данных (файлы как в игре): из готового пака (`import_vpk`) или в редакторе набора (`SetEditor`: все медали 0–8, 8a–8c и звёзды 1–5, `import_image`/`reset_slot`; картинка подгоняется под размер текстуры, маленькая версия медали делается сама); набор кладётся в пак целиком, подмена ранга — поверх |

| `tools/shop_build.py` | ручной запуск того же: `python tools/shop_build.py` (собрать), `... off` (удалить) |
| `tools/export_builds.py` | выгрузка данных сборок (GitHub Actions) |
| `tools/gen_ability_info.py` | пересоздаёт `app/assets/abilities.json` из Dota |

## Как работают моды Dota
- **Маркер:** видимый маркер рисуют частицы `particles/ui_mouseactions/clicked_occlusion_*` (обычные `clicked_*` подмена не затрагивает). Родные частицы цвет из чисел не берут — нужны пересобранные (с `m_ConstantColor`/`m_vecColorScale`). Заготовки лежат в `app/assets/marker` (цвет в них (99, 60, 175) — `TEMPLATE_RGB`), `recolor_template` подставляет свои цвета. Это родные частицы Valve, пересобранные общим сборщиком модов `d2pfx_compiler` (подпись внутри файла), такие же лежат в любом паке маркера; моды нового типа красят не числами, а перекрашенными текстурами (`*_цвет.vtex`). Своя пересборка из родных файлов — задача на будущее (нужен писатель KV3). Форма лепестков — текстура `materials/particle/arrow_down.vtex_c` (DXT5 128×128, рисуем сами).
- **Магазин:** в `panorama/scripts/hud/dota_hud_shop.vjs_c` дописывается наш JS. Он скрывает родные сборки (`ItemBuild`, `ItemPlusGuide`) и рисует свою панель с данными из `DATA` (вкладки позиций 1–5, предметы, прокачка, таланты). Герой определяется через `Players.GetPlayerSelectedHero`, тик раз в секунду.
- **Размер панели магазина** как у родного гайда (`dota_hud_shop.css`/`dota_hud_item_build.css`): колонка `#GuideFlyout` 210 px (`GUIDE_W`; с Dota Plus игра растягивает её до 540 — прибиваем ширину каждый тик), предметы 42×31 с отступами 6/5 (4 в ряд), заголовки 14 px, отступ слева 12, фон `bg_shop_guide_psd`.
- **Режим сборок** на главном окне: «В магазине Dota» (ставит пак, оверлейные сборки и автооткрытие выключены) или «Оверлей» (пак убирается). Режим определяется по наличию пака (`ControlPanel.builds_mode`).
- **ВАЖНО для JS в Panorama:** панели магазина НЕ удаляем (`DeleteAsync` роняет игру) — блоки героев создаются один раз и прячутся/показываются.
- **Данные сборок:** `https://raw.githubusercontent.com/Fyogra/CoolColorCursor/main/data/builds/{id}.json` (позиции 1–5 → фазы предметов, `skills.order`, `talents`). Предметы и таланты — Stratz; порядок прокачки — настоящие цепочки из про-матчей OpenDota за 90 дней (`real_skills`, `skills.source = "opendota"`; меньше 8 игр на позиции — цепочки героя по всем позициям, у героя меньше 8 игр — матчи за 180 дней; лимит OpenDota (429) — одна повторная попытка через минуту). **Прокачка — только из OpenDota** (решение пользователя): прикидки Stratz больше нет; не ответила OpenDota — `export_builds.keep_old_skills` оставляет прокачку из прошлой выгрузки. `skill_order.legalize` раскладывает очки по уровням; шард/аганим/врождённые (добавки из `s` в `abilities.json`) качаются, только если есть в статистике.

## Что делать после патча Dota
1. Обычно ничего: прога сама замечает обновление игры, пересобирает список скиллов и пак магазина (при закрытой Dota). Вручную: `python tools/gen_ability_info.py`, затем `python tools/shop_build.py`.
2. Магазин не показывается или игра падает → удалить наш пак магазина из `game\dota_russian` (`python tools/shop_build.py off`), смотреть, не поменялся ли `dota_hud_shop.vjs_c`/названия панелей (`ItemBuildContainer`, `DOTAHUDShop`).
3. Маркер не красится → кнопка «Вернуть как было» (или удалить наш пак маркера), проверить `clicked_occlusion_*` в новой версии (VRF: `Source2Viewer-CLI`).
4. Ничего не помогает → удалить все `pak6x_dir.vpk` из `game\dota_russian`, игра будет обычной.
5. Пак магазина обновляется сам (раз в сутки и после обновления игры); состояние — `shop_state.json` в папке данных. Если игра изменила скрипт магазина, `build()` вернёт ошибку «нужна правка сборщика» (смотри лог).

## Инструменты
VRF (Source2Viewer CLI) — декомпиляция `.vpcf_c/.vtex_c/.vxml_c/.vjs_c`. Для проверки Qt без экрана: `QT_QPA_PLATFORM=offscreen python`.
